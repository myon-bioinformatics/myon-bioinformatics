# 制約下の設計パターンと横断実験

目的は、限られたトークン・通信・メモリ・描画時間・CI時間の中で、
必要な品質を維持しながら総費用を減らすこと。既存の成熟した技術や
ゲーム機の資源節約から着想し、各リポジトリの実測で採否を決める。
ここでの対応表は設計案であり、歴史的な実装の出典検証ではない。

| 再利用する工夫 | 横断できる設計 | 適用先・実験 | 採用条件・破綻条件 |
| --- | --- | --- | --- |
| タイル・辞書の再利用 | 共有辞書と短い参照 | TalkCompress: 辞書配布＋本文＋再送の累積費用。mcp-toolcall-lab: 同じ入力でタスク成功率を比較 | 初期配布込みで削減。辞書不一致、短縮語衝突、途中参加、再配布を検証 |
| パレット・表現数の制限 | 限定語彙・スキーマ | mcp-toolcall-lab: ツール名・引数の短縮表現を通常JSONと比較 | 同じ予算で誤呼び出しを増やさない。未知の引数・版ずれは明示的に検出 |
| フレーム処理予算 | 上限内で重要な処理を優先 | xprobe: 同じ件数・時間でseed/greedyの境界被覆と検出力を比較 | 選択自体の時間も算入。予算切れを成功扱いしない |
| 差分更新と全体照合 | 変化分をまとめ、スナップショットで復旧 | 親子監査・Aoi: 変更内容のある参照だけ更新し、全体監査を残す | 参照・ハッシュ検証を省略しない。欠落・順序逆転・再試行で復旧できる |
| 表示と内部表現の分離 | 一つの構造化データから複数表示 | Ironmate・Aoi: PPTX/SVG/Webの意味的一致 | 構造一致と描画結果を別に検査。フォントや数値の表現境界を検証 |
| 画面外を描画しない | 仮想化と表示部品から独立した状態 | web-ui: 大量要素でDOM数・更新時間・状態保持を比較 | フォーカス、キーボード、検索、リサイズ、画面読み上げを維持 |
| ビット詰め・固定幅 | 必要な区別だけ密に格納 | xprobe・Ironmate: ビット境界、符号、桁あふれ、Unicode/UTF-16境界を入力生成 | 不正offset、長さ、byte order、端数ビットを検証。可読性・復旧費用も記録 |

## UIの集約先

新しいUI拡張・性能実験は **web-ui** に集約する。
flutter_navigation_basic は今後の吸収・終了を前提に、必要な保守と移行整理を行う。
既存のリサイズ時の状態保持やブラウザ回帰テストは、web-uiへ移す知見として扱う。
この文書自体はFlutterの削除・アーカイブ・移行処理を実行しない。

## 共通の実験記録

実装をすぐ共通ライブラリ化せず、まず同じ比較の型を使う。

1. 制約: 上限値、測定単位、対象環境、入力・seedを記録する。
2. 比較対象: 素朴な方式と提案方式を同一入力・予算で比較する。
3. 全体費用: 初期化・辞書配布・更新・失敗・復旧・選択処理も含める。
4. 品質: 完全往復、意味保持、タスク成功率、境界検出率を混同しない。
5. 破綻条件: 欠落・衝突・境界超過・再接続・版ずれを含める。
6. 結果: 元データ、実行コマンド、commit、測定器、既知の除外費用を残す。
7. 採否: 得になる規模と逆効果になる条件を示す。改善なしも保存する。

## 初回の実装順

1. TalkCompressの既存RuleBookに、読み取り専用のセッション費用実験を追加。
   標準ライブラリのみでバイト費用と完全往復を測り、任意のtokenizer計数を注入可能にする。
2. その結果を受け、mcp-toolcall-labで実tokenizerとタスク成功率を測定。
3. xprobe/Ironmateの予算・境界実験、web-uiの描画実験を独立PRで進める。

初回は方式と測定の足場を作る段階。全リポジトリへの導入やモデル実測が
完了したとは扱わない。親の監査・vendor管理は引き続き親リポジトリ内に置く。
